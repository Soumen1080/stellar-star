# Account deletion workflow

`POST /api/account/delete` starts a persistent workflow and can resume it after an error. Migration `0020_account_deletion_state_machine.sql` is required, as is the server-only Supabase service role key. The first transaction records `deleted_accounts` before any erasure, so RLS, API tokens, refresh, and all session-backed API routes fail closed immediately.

The worker then cancels reminder schedules and payment requests, ends recurring jobs, removes the deleted member from future recurring templates, dismisses generated drafts, removes webhook subscriptions and queued payloads containing the wallet, erases receipt objects from the private storage bucket, anonymizes receipt metadata and shared member names, removes profiles and private contacts, and redacts personal identifiers from retained application logs. Each successful phase is recorded against a request UUID with counts only; the evidence rows contain no wallet address, file path, content, or error text. A failed phase is retryable and earlier phases are safe to repeat.

An active legal hold in `account_legal_holds` pauses erasure while retaining the account's data under revoked access. Operations can place a hold by inserting the uppercase wallet and an opaque reference. Release it by setting `released_at`; the user can then retry the deletion endpoint, or operations can invoke the workflow from a controlled server job. Never place a case narrative or personal details in `hold_reference`.

Financial history and public Stellar records are retained where needed to preserve shared accounting and legal evidence. In shared expenses and trips, names are replaced with `Former Member`; wallet attribution needed for the financial record remains. Private receipts, contacts, profile records, invitations, reminders, templates, and webhook payloads are removed. Database backups follow the 30-day expiry in the retention policy; storage objects are deleted during the workflow.

After deploying the migration and workflow to staging, create a synthetic wallet, attach a receipt, create reminder/template/webhook records, request deletion, and run `node scripts/verify-account-deletion.mjs` with `DELETE_VERIFY_WALLET` set to that wallet. Run the same read-only check after the backup retention window has elapsed to verify the operational retention process; the script prints no wallet identifier or user content.
